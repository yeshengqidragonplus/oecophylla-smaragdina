# Oecophylla smaragdina

一个用于小型局域网（内网）简单通信的 VS Code 插件：侧边栏聊天界面，支持点对点文本消息与文件传输，自动发现同网段的其他实例，无需任何中心服务器。

## 功能特性

- 在 VS Code 侧边栏提供聊天界面
- 局域网内自动发现其他实例（含同一台机器上的多个 VS Code 实例）；每块网卡都发广播，广播被过滤时还会持续单播探测已配置的联系人，也可手动"扫描网段"
- 对方换了 IP（DHCP）仍是同一个联系人，不会出现重复条目
- 点对点文本消息与文件传输（文件分块发送，实时进度）
- 在线状态三态显示：🟢 在线 / 🟡 单向可达（对方能找到你，你到对方可能被防火墙拦截）/ ⚪ 离线；状态栏显示在线人数
- 收到消息时侧边栏不可见会有未读徽标与通知
- 内置诊断：`OS Chat: 运行诊断` 汇总网卡、端口、对端状态与网络错误，并按系统给出防火墙放行建议
- 可配置聊天对象（peers.json，可手工维护）

## 使用方法

1. 安装插件后，点击活动栏的机器人图标打开聊天视图。
2. 网络服务默认随 VS Code 启动自动启动（`oschat.autoConnect`）；也可执行 **启动网络服务** / **停止网络服务** 命令。端口与昵称在设置里配置，修改后需重启网络服务。
3. 同一局域网内启动了本插件的其他机器会自动出现在列表中；也可通过 **编辑聊天对象** 手工添加。
4. 选择聊天对象即可发送消息或文件；接收的文件保存到 `oschat.downloadPath` 配置的目录。

### 主要命令

- **启动网络服务** / **停止网络服务** - 启停局域网通信服务
- **新建会话** - 创建新的聊天会话
- **编辑聊天对象** - 管理聊天联系人（也可直接 **打开 peers.json 文件** 编辑）
- **设置** - 配置插件参数
- **运行诊断** - 找不到对方时使用：生成可复制的诊断报告
- **扫描网段** - 广播被过滤的网络里使用：向本机所在网段的每个地址发一个探测包（需确认）

## 网络与防火墙要求

插件使用以下端口（详细协议设计见仓库中的 docs/DESIGN.md）：

| 端口 | 协议 | 用途 |
|------|------|------|
| `oschat.port`（默认 8080） | UDP | 发现应答与心跳 |
| 41320（固定，所有实例共享） | UDP | 接收广播发现请求 |
| `oschat.port` + 1000（默认 9080） | UDP（KCP） | 聊天消息与文件传输 |

如果对方一直显示离线或发现不到，先执行 **运行诊断**；常见原因是防火墙没有放行上述端口（Windows 注意"公用"网络配置文件，macOS 15 起需允许"本地网络"权限）。对方显示 🟡 通常说明有一端的入站被拦截。

## 配置项

所有设置都是机器级（不会被 Settings Sync 同步到另一台机器）。

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `oschat.port` | UDP 主端口（1024–64535）；业务端口为此值 + 1000，另需放行固定的发现端口 41320 | 8080 |
| `oschat.nickname` | 你的昵称（可选），留空使用计算机名 | "" |
| `oschat.autoConnect` | VS Code 启动后自动启动网络服务 | true |
| `oschat.peersFilePath` | peers.json 保存的文件夹路径，留空使用扩展全局存储目录 | "" |
| `oschat.downloadPath` | 接收文件保存的文件夹路径，留空使用扩展全局存储目录下的 downloads | "" |

peers.json 格式示例：

```json
[{ "ip": "192.168.1.100", "port": 8080, "nickname": "用户A", "hostname": "PC-A" }]
```

## 已知限制

- 协议不加密、无身份认证，仅适用于受信任的小型内网环境
- 聊天记录保存在本机（扩展全局存储目录的 chatSessions.json），暂无清理与导出
- 仅支持 IPv4；同一台机器上第二个 VS Code 窗口会因端口被占用而无法启动网络服务
- 不支持群聊和跨网段（NAT）通信

如有问题请在 GitHub 提交 Issue。

## 开发

- `npm run watch` - 开发模式（F5 启动 Extension Development Host 调试）
- `npm run compile` - 类型检查 + lint + 打包
- `npm run test:unit` - 单元测试（不启动 VS Code）
- `npm run test` - 集成测试（需要 VS Code 环境）
- `npm run compile-tests && node smoke-test.js` - 端到端冒烟测试（同机双实例互发消息/文件，不依赖 VS Code）

架构与协议设计详见仓库中的 docs/DESIGN.md，开发约定见 CLAUDE.md。
